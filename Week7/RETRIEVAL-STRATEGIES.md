# Retrieval Strategies 

## 1. Goal

The goal is to increase precision, reduce hallucination, and produce traceable, high-quality context for LLMs by implementing advanced retrieval strategies in our RAG system. This includes:
- Hybrid retrieval (semantic + keyword)
- Reranking
- Deduplication
- Max Marginal Relevance (MMR)
- Context engineering with source attribution

## 2. Hybrid Retrieval Strategy

### Semantic Search (Vector-based)

- Uses dense embeddings generated by Sentence-Transformers
- FAISS vector database performs similarity search
- Strength: captures semantic meaning
- Weakness: may miss exact keyword matches


### Keyword Search (BM25 Fallback)

- Uses BM25 ranking over tokenized chunks
- Strength: exact keyword matching
- Weakness: lacks semantic understanding

### Hybrid Combination

Hybrid retrieval merges:
- Semantic candidates (high recall)
- Keyword candidates (high precision for exact terms)

This ensures:
- Important information is not missed
- Queries with domain-specific terms are handled correctly

## 3. Reranking Strategy

### Cosine Similarity Reranking

- Each candidate chunk is rescored against the query
- Cosine similarity is computed between query and chunk embeddings
- Candidates are reordered by relevance score


## 4 Deduplication Strategy

### Problem

Documents often contain:
- Repeated sentences
- Overlapping chunks
- Near-duplicate information


### Solution

- Compute cosine similarity between chunks
- Remove chunks with similarity above a defined threshold
- Retain only unique information


## 5. Max Marginal Relevance (MMR)

### Why MMR?

High relevance alone can still produce redundant context.
MMR balances:
- Relevance to query
- Diversity among selected chunks

## 6. Context Engineering

### Context Window Optimization

- Limit total context size (characters/tokens)
- Select top-ranked, diverse chunks
- Ensure compatibility with LLM context limits


### Traceability

Each context block includes:
- Source document
- Page number or row identifier
